# GET /techs/{player_identifier}



**Конечная точка:** `GET /v1/pdapi/techs/<player_identifier>`

**Аутентификация:** Токен носителя

**Разрешение:** `REST.Techs.Read`

## Цель

Содержит технологическую информацию для игрока. Идентификаторы технологий можно найти на [paldeck.cc/technology](https://paldeck.cc/technology).

## Параметры пути

- `player_identifier`: `UserId` или `PlayerUID` для целевого игрока.

## Параметры запроса

Нет.

## Тело запроса

Нет тела запроса.

## Схема ответа

--8<-- "_snippets/restapi/schemas/techs.md"

## Реакции на ошибки

Тела ошибок используют следующую форму:

```json
{
    "Error": {
        "Code": "ERROR_CODE",
        "Message": "Human-readable message",
        "Details": {}
    }
}
```

| HTTP | Код ошибки | Когда это произойдет |
|------|------------|-----------------|
| `401` | `INVALID_TOKEN` | Заголовок `Authorization` отсутствует, имеет неправильный формат или не соответствует настроенному токену носителя. |
| `403` | `MISSING_PERMISSION` | Токен действителен, но не включает это разрешение конечной точки. |
| `400` | `INVALID_JSON` | Текст запроса был предоставлен, но его не удалось проанализировать как JSON. |
| `400` | `REQUEST_FAILED` | Не удалось определить целевого игрока, учетную запись игрока, данные технологии или таблицу технологий. |
| `500` | `REQUEST_TIMEOUT` | Обратный вызов внутреннего игрового потока не завершился в течение 5 секунд. |

## Примеры

### Чтение разблокированных технологий по UserID

```http
GET /v1/pdapi/techs/gdk_2533274812345678
```

### Чтение разблокированных технологий по PlayerUID

```http
GET /v1/pdapi/techs/f0a1c3e9-7d5b-4a28-8c33-411fdc2e6b74
```

## Сценарии

- Проверьте, есть ли у игрока [`TechID`](https://paldeck.cc/technology), прежде чем выучить его или забыть.
- Создайте страницу администратора, которая разделяет разблокированные и доступные технологии.
- Аудит прогресса после действий поддержки.
