## エラー応答

このエンドポイントは非推奨となっており、現在のビルドには存在しない可能性があります。利用可能な場合、エラー本文は現在の API と同じ REST エラー エンベロープを使用します。

| HTTP |エラーコード |それが起こったとき |
|------|------------|-----------------|
| `401` | `INVALID_TOKEN` | `Authorization` ヘッダーが欠落しているか、形式が不正であるか、構成されたベアラー トークンと一致しません。 |
| `403` | `MISSING_PERMISSION` |トークンは有効ですが、この非推奨のルートに対するアクセス許可が含まれていません。 |
| `400` | `INVALID_JSON` |リクエスト本文が指定されましたが、JSON として解析できませんでした。 |
| `400` | `REQUEST_FAILED` |リクエストの検証または適用中に従来の報酬操作が失敗しました。 |
| `500` | `REQUEST_TIMEOUT` |内部ゲーム スレッド コールバックは 5 秒以内に完了しませんでした。 |

??? info "POST `/v1/pdapi/give` — EXP / アイテム / 仲間 / 卵を付与（アトミック）"
    ## POST `/v1/pdapi/give`
    ### 何をするのか
    単一のサーバー側トランザクションのような操作でターゲット プレーヤーに報酬を付与します。

    - 経験値および/または
    - アイテムおよび/または
    - 友人および/または
    - 卵
    リクエスト本文に応じて。

    ### 核となる行動
    このエンドポイントは **アトミック**に動作することを目的としています。

    - すべてが許可されるか
    - または何も許可されない

    いずれかの部分が失敗した場合 (無効な入力、インベントリ スペースの不足、無効な ID など)、サーバーはリクエストを拒否し、部分的に適用しない必要があります。

    ### なぜこれが重要なのか
    管理ツールは誤って次のようなことをしてはなりません。

    - EXPは与えられますが、アイテムは与えられません
    - いくつかのアイテムを与えたが、後のアイテムでは失敗する
    - アイテムを置かずに仲間をスポーン

    アトミックな動作により、混乱した状態や「地獄からのサポートチケット」が回避されます。

    ### 叶えられるもの
    実装によっては、リクエストには次のものが含まれる場合があります。

    - `EXP` — 経験を追加します
    - `Relics` — レリック タイプをキーとしたレリック ポイントを追加します
    - `TechnologyPoints` — 技術ポイントを追加します
    - `AncientTechnologyPoints` — 古代の技術ポイントを追加します
    - `UnlockTechnology` / `Techs[]` — テクノロジーを学ぶ
    - `Items[]` — 1 つ以上のアイテムにカウントを与える
    - `Pals[]` — ID + レベルで友達を与える
    - `PalTemplates[]` — ファイル名で pal テンプレートをインポート
    - `PalEggs[]` — ID + 仲間 ID / テンプレートによる卵、オプションでレベル付き


    ### エラー応答

    このエンドポイントは非推奨となっており、現在のビルドには存在しない可能性があります。利用可能な場合は、現在の API で使用される同じ REST エラー エンベロープが期待されます。失敗したベアラー認証の場合は `INVALID_TOKEN` (`401`)、トークンが認証されたがルートの呼び出しが許可されていない場合は `MISSING_PERMISSION` (`403`) です。リクエスト検証の失敗は、JSON エラー オブジェクトとして返されます。エンドポイント固有のエラー コードについては、分割報酬エンドポイントに移行します。

    ### 例

    ```json
    {
        "UserID": "steam_76561198012345678",
        "EXP": 25000,
        "Items": [
            { "ItemID": "Money", "Count": 10000 }
        ]
    }
    ```

    ```json
    {
        "UserID": "steam_76561198012345678",
        "Pals": [
            { "PalID": "Pengullet", "Level": 10 }
        ],
        "PalEggs": [
            { "EggID": "PalEgg_Fire_01", "PalID": "Foxparks", "Level": 12 }
        ]
    }
    ```

    ### 検証と一般的な失敗例
    管理者がエラーに遭遇する一般的な理由は次のとおりです。

    - 在庫スペース: すべてのアイテムを入れるのに十分なスペースがない → リクエスト全体が失敗する
    - 無効な ID: 不明な `ItemID`、`PalID`、`EggID`、またはテンプレート ファイルが見つからない → 失敗
    - 無効な値:
        - マイナス/ゼロのカウント (ルールによる)
        - 無効なレベル (低すぎる/高すぎる、または数値以外)
        - 必須フィールドが欠落しています (例: `UserID` がありません)
    - プレーヤーが見つからない/ロードされていない:
        - ユーザーIDが不明
        - プレーヤーは現在オンラインではありません (サーバーがオフライン許可を処理する方法によって異なります)

    ### 返品
    エラー数とエラーメッセージ。ステータスが 200 でない場合は、`Errors` で発生したエラーの数を確認してください。 `Error` には、失敗した内容の詳細なリストが含まれています。
